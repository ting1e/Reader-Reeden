# S3 本地进度自动纠正

适用于 OpenList S3 将 `book_progress/*.json` 保存到真实本地文件系统的部署。
默认关闭；关闭时不记录纠正快照、不监听该用户目录、不回写纠正进度。
原来的阅读、S3 同步流程保持不变。

## 启用

1. 安装 `requirements.txt` 依赖，执行 `python manage.py migrate`。
2. 在「用户设置 → S3 设置」填写**本地进度目录**并启用自动纠正。
   填写 `book_progress` 目录本身，而不是单个 JSON 文件或 S3 URL。
3. 在与 Reader 使用相同数据库和配置的环境运行一个独立后台进程：

   ```sh
   python manage.py watch_s3_progress
   ```

   生产部署请使用 systemd、进程管理器或独立容器保持进程运行。
   不要为同一数据库启动多个监听进程。

设置变更约一秒内生效；未启用任何用户时不建立目录监听。
监听写入关闭和原子重命名事件，合并约 200ms 内的重复事件。
启动或切换目录时扫描已有文件建立基线，不执行纠正。
进程停机期间的中间覆盖不会被捕获。

## Docker

Web 服务与监听进程均需能访问设置中的目录，供保存设置时校验路径。
将 OpenList 实际进度目录只读挂载到二者，例如：

```yaml
volumes:
  - ./local:/app/local
  - /实际/openlist/book_progress:/app/s3-progress:ro
```

设置中填写 `/app/s3-progress`。监听容器使用相同镜像、数据库挂载和环境配置，
命令为 `python manage.py watch_s3_progress`；Web 服务仍保持原启动命令。
纠正通过用户配置的 S3 接口完成，不直接写挂载目录。

## 规则

同一设备两次观察到的进度间隔至少 10 分钟，位置差绝对值不超过 2000 字；
服务器保存的真实阅读进度时间严格位于两者之间，且位置领先于两者时回写。
字数位置按正文位置换算，不以全书百分比差代替。
同一用户同一本书，从首次成功纠正起 5 分钟内最多成功纠正两次；失败不计数。
回写使用当前时间，但保留服务器快照的原始阅读时间。
服务器自身回写不计作设备同步，JSON 的统计和其他非位置字段保持不变。

设备 JSON 需包含 `bookId`、`deviceId`、`lastReadTime` 及位置字段，
文件名为书籍 MD5；书籍需已导入 Reader，启用后需有实际阅读保存以建立服务器快照。
不处理回看误判及并发覆盖冲突，也不强制保留最大进度。
关闭功能不撤销已经完成或已经发出的回写。
